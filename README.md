# Stackshot

Paste a GitHub repo, get a designed card of what it's actually built with, sorted into
frontend, backend, infrastructure and tooling. It comes as two PNGs you embed in a README,
so the card follows each reader's light or dark theme.

**Live:** https://stackshot.ilerioluwa.com

## Use it

Paste a repo on the site, pick a style, and copy the snippet. Or write the URL yourself:

```
https://stackshot.ilerioluwa.com/{owner}/{repo}/{style}-{theme}.png
```

`style` is `tiles` or `terminal`, and `theme` is `light` or `dark`. A README needs both
themes, so the snippet is a `<picture>` element:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="https://stackshot.ilerioluwa.com/OWNER/REPO/tiles-dark.png">
  <img alt="OWNER/REPO tech stack, generated by Stackshot" src="https://stackshot.ilerioluwa.com/OWNER/REPO/tiles-light.png">
</picture>
```

Leave `width` and `height` off the `img`. A card is as tall as its stack, and a repo that
later fails to resolve gets a shorter error card at the same URL.

## Why it isn't just reading package.json

That was the naive version, and it produces embarrassing output on real repositories. The
interesting work is in four places.

**1. GitHub never fetches your image for the reader.**
Every README image goes through Camo, GitHub's proxy, which fetches once, sanitises and
serves from its own cache. That one constraint decides most of the design. SVG is out,
because Camo strips `@font-face` and custom type never loads. Theme-aware images are out,
because a media query inside a proxied image never sees the reader. Per-view analytics are
out too. The supported path is a `<picture>` element with two separate PNGs, so every
stack renders twice and the cache has to be good.

**2. The card has to survive 350 pixels.**
On GitHub's phone apps a 1200-unit card is drawn about 350px wide, so one unit is 0.29px.
Everything is built back from that number. Technologies are two-letter symbols in type, not
logos, because a symbol survives 0.29 and a logo's licence and aspect ratio don't.
Descriptions live on the site, not the card. Colour names the layer, because the Tiles grid
has no up or down to carry it.

**3. Detection is a union over a file tree, not a manifest read.**
One recursive Trees API call returns every path in the repo. From it, up to six manifests
are picked by priority: the root `package.json`, then the root language manifest
(`pyproject.toml`, `requirements.txt`, `go.mod`, `Cargo.toml`, `Gemfile`, `composer.json`),
then the `Dockerfile` and Compose file, then the first CI workflow, then the remaining
manifests anywhere in the tree, shallowest first. Monorepos work without resolving any
workspace globs, because the tree already says where the manifests are.

Lockfiles are never parsed. A dependency that appears only in a lockfile is transitive, and
transitive dependencies are noise.

**4. The cache is keyed on content, not commits.**
Rendering is a pure function of the extracted stack and a theme: same input, byte-identical
PNG, enforced by a test. So renders are keyed on a hash of the stack rather than the commit,
and a README typo costs two API calls and no render. Showing major versions only
(`Next.js 15`, not `^15.1.0`) means patch bumps don't invalidate anything either.

A cold resolve costs **two authenticated API calls**: one GraphQL query and one tree.
Manifest contents come from `raw.githubusercontent.com`, pinned to the resolved commit,
which doesn't touch the API's rate limit.

## Measured

Numbers from production, not estimates.

- **65 real repos, cold, before launch:** every popular JavaScript monorepo, plus Python,
  Go, Rust, Ruby and PHP projects, renamed, archived, missing and manifest-less repos. No
  timeouts and no wrong error cards. The slowest whole responses were microsoft/TypeScript
  at 6.3s and vercel/next.js at 6.2s, under the roughly 8 seconds Camo waits.
- **225 technologies** in the curated map, across four layers.
- **1,050 tests**, with no network: every GitHub response is a committed fixture.
- **Two API calls per cold resolve**, asserted by a test, against 5,000 an hour.

## Architecture in one diagram

```
  url ─▶ resolve ─▶ StackDoc ─▶ sha256 ─▶ render ─▶ PNG ─▶ CDN ─▶ Camo ─▶ reader
         (network)  (data)      (key)     (pure)          (cached) (opaque)
```

Only route handlers know a network exists. Everything below them is pure functions over
committed fixtures, which is why the test suite never touches the network.

The full version, with its invariants, is in [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## Hard parts

| Problem | Approach |
|---|---|
| A theme-aware image behind a caching proxy | Two PNGs and a `<picture>` element ([ADR-0003](./DECISIONS/0003-two-pngs-picture-element.md)) |
| Legibility at 350px | Two-letter symbols, layer colour, descriptions moved off the card ([ADR-0029](./DECISIONS/0029-card-styles.md)) |
| Logos: licensing, aspect ratios, missing assets | No logos. Type instead ([ADR-0002](./DECISIONS/0002-type-not-logos.md)) |
| Monorepos without a workspace resolver | A union of manifests across the tree ([ADR-0001](./DECISIONS/0001-detection-scope.md)) |
| `Next.js` implies `React`, and listing both is noise | A `suppresses` field on each map entry ([ADR-0006](./DECISIONS/0006-stack-map-as-typed-module.md)) |
| Rate limits on a public endpoint nobody controls | Content-hash cache, negative cache, raw fetches, and a guard that keeps the last 10% of the hour for people on the site ([ADR-0040](./DECISIONS/0040-the-global-budget-guard.md)) |
| A broken image in a stranger's README | Every failure renders an error card at HTTP 200 ([ADR-0007](./DECISIONS/0007-errors-render-a-card.md)) |
| Changing the default style without restyling cards already embedded | The style is always written in the URL, and the legacy `card-*.png` is pinned forever ([ADR-0029](./DECISIONS/0029-card-styles.md)) |

## Limitations, honestly

- **Public repos only.** Private repos would need a GitHub App and an install flow.
- **Versions are declared floors, not installed versions.** `^15.1.0` renders as `15`.
  The installed version lives in a lockfile, which this deliberately doesn't parse.
- **`<picture>` follows your OS colour preference, not your GitHub theme setting.** If they
  disagree, you see the card matching your OS. There is no fix for this.
- **The map is curated, not exhaustive.** Anything unrecognised is dropped rather than
  guessed at, and logged as the backlog.
- **A project's own card can't name itself.** vuejs/core has no Vue tile, because Vue is
  the repo, not something it depends on.
- **Embedded cards update slowly, on a schedule we set.** Camo honours our `cache-control`,
  so a changed stack takes up to about 25 hours to reach every reader, mostly in our own
  CDN ([ADR-0026](./DECISIONS/0026-cache-chain.md)).
- **Huge repos may be sampled.** The Trees API truncates, so we fall back to the root
  listing and mark the result partial.
- **Docker and CI signals are matched by pattern, not parsed.** They rank below declared
  dependencies and are the first thing cut when a layer is full.
- **There are no view counts, and there never will be.** Camo hides every reader. What is
  counted is cards generated, snippets copied and READMEs found by GitHub search
  ([ADR-0012](./DECISIONS/0012-analytics.md)).

## Scope

**In:** paste a URL, generate the card in one of a few fixed styles, download the PNGs, copy
the embed snippet.

**Out:** accounts, saved cards, a theme editor, private repos, comparison mode, an iframe
embed, a public API.

This is a small tool built deliberately small. The reasoning is all committed:
[`DECISIONS/`](./DECISIONS) says why each choice was made and what would change it, and
[`GOTCHAS.md`](./GOTCHAS.md) records what went wrong along the way.

## Running locally

```bash
pnpm install
cp .env.example .env.local   # GITHUB_TOKEN, UPSTASH_REDIS_REST_URL, UPSTASH_REDIS_REST_TOKEN
pnpm dev
```

```bash
pnpm test                                    # no network, fixtures only
pnpm tsx scripts/resolve.ts vercel/next.js   # print a StackDoc
```

A local server writes under a `local:` prefix in Redis, so it never touches production's
cache. It is also much further from GitHub and Upstash than a deployment is, so a huge repo
can time out locally that resolves fine in production.

## Adding a technology

One entry in `lib/stack-map/entries/`:

```ts
{
  id: "drizzle",
  display: "Drizzle",
  symbol: "Dr",
  category: "backend",
  weight: 78,
  description: "SQL-shaped TypeScript ORM.",
  aliases: ["npm:drizzle-orm", "npm:drizzle-kit"],
  versionFrom: ["npm:drizzle-orm"],
}
```

`aliases` are the package names that mean this technology, written as
`<ecosystem>:<name>`. The integrity test checks that ids and symbols hold together, that
every `suppresses` target exists, and that nothing is both mapped and denied.
`pnpm tsx scripts/symbol-sheet.ts` draws every entry as a tile, so you can check a new
symbol the way a stranger would read it. PRs welcome.
